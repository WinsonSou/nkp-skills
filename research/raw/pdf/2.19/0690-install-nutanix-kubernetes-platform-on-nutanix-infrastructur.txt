Maximum Transmission Unit Configuration for AHV Clusters
Learn how Nutanix Kubernetes® Platform configures maximum transmission unit values for AHV clusters
that use Cilium with overlay networking.
For AHV clusters, the AHV vSwitch default maximum transmission unit (MTU) is 1500. AHV built-in IP
address management (IPAM) passes this value to cluster virtual machines through DHCP Option 26.
When you use Cilium with overlay networking such as Geneva, Cilium automatically reduces the outbound
encapsulated interface MTU by 50 bytes. With the default 1500 value, the effective encapsulated MTU is
1450.
This default configuration aligns the underlay and overlay MTU values. This alignment helps prevent
packet fragmentation caused by encapsulation overhead.
Configuring Jumbo Frames
To use jumbo frames, configure MTU at the infrastructure layer first. Ensure the physical network
infrastructure is configured for the same MTU end to end:
•
Set the required MTU on the AHV vSwitch.
•
Configure subnet MTU settings as required for your subnet type. Basic subnets do not enforce MTU
by default and align with the vSwitch MTU. Configure MTU explicitly for advanced subnets or VPC
subnets.
After you update these settings, AHV passes the new MTU to the virtual machines through DHCP Option
26. Cilium applies the same 50-byte reduction for overlay encapsulation. For example, if the infrastructure
MTU is 9000, the encapsulated MTU is 8950.
Using External DHCP
If you use an external DHCP server instead of AHV built-in IPAM, configure DHCP Option 26 with the
correct MTU value. Incorrect or missing DHCP Option 26 values can result in suboptimal MTU usage. For
example, the backbone network can use an MTU of 9000 while virtual machines remain at 1500.

Before you begin
Before you update your Prism Central trust bundle on deployed Nutanix Kubernetes Platform (NKP)
clusters, ensure all requirements of Prism Central Credentials are met. For more information, see Prism
Central Credential Requirements.
About this task
To update the Prism Central trust bundle, follow these steps:
Procedure
1. Update the CAPX information:
a. Base64 encode the new PC SSL certificate.
b. Update the additionalTrustBundle field in the impacted cluster's specification with the new
base64 encoded certificate:
kubectl edit cluster -n <namespace> <cluster-name>
The additionalTrustBundle information is located in the cluster's YAML/JSON as
spec.topology.variables[].name.clusterConfig.value.nutanix.prismCentralEndpoint.additionalTru
To verify the NutanixCluster object is updated with the new SSL certificate, run the kubectl get
cluster -n <namespace> <cluster-name> command:
kubectl get cluster -n <namespace> <cluster-name> 
  apiVersion: infrastructure.cluster.x-k8s.io/v1beta1
  kind: NutanixCluster
  metadata:
    name: <cluster-name>
    namespace: <namespace>
  spec:
    prismCentral:
      additionalTrustBundle:
        data: |-
          -----BEGIN CERTIFICATE-----
  <CERTIFICATE CONTENT>
          -----END CERTIFICATE-----
        kind: String
        name: ""
        namespace: ""
2. Update the information in Nutanix CCM:
a. Fetch the HelmChartProxy object belonging to the Nutanix CCM:
kubectl get hcp -n <cluster namespace> | grep nutanix-ccm
b. Update the prismCentralAdditionalTrustBundle field, located in the spec.valuesTemplate by
using the namespace and HCP name from the previous step:
kubectl edit hcp -n <cluster namespace> <HCP Name>
