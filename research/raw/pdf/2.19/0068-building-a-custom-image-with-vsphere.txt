Before you begin
Before creating an image, ensure your base template meets the following requirements:
•
The base template must be a vSphere VM template (not a VM) and must be powered-off.
•
The template must be accessible from the vCenter server and located in the specified datacenter.
•
The default user must have sudo privileges.
•
Ensure that you install and enable the SSH server.
•
Ensure that you install and configure cloud-init.
•
Ensure that you install Python version 3.x and it is accessible.
•
Ensure availability of at least 20 GB of disk space on the root file system.
•
Network configuration must allow SSH access during the build process.
•
Ensure that no existing Kubernetes components are present.
•
The template must have VMware Tools installed (recommended for optimal performance).
About this task
To create a custom OS image, you can use the nkp create image vsphere command with required flags,
or follow the comprehensive procedure below to configure all options using the environment variables:
Procedure
1.
Open the terminal with access to NKP CLI.
2.
Choose the operating system:
export OS_TYPE=Operating System Type
For more information, see Supported Infrastructure Operating Systems on page 13.
3.
Provide vCenter server credentials:
export VSPHERE_USERNAME=vCenter username
export VSPHERE_PASSWORD=vCenter password
Replace:
•
vCenter username with the username to access vCenter
•
vCenter password with the password to access vCenter
The NKP CLI needs these credentials to access vCenter.
4.
Provide the vCenter server host:
export VCENTER_SERVER=vCenter server host or IP
Replace vCenter server host or IP with the host IP or FQDN of the vCenter API server.
5.
Choose the base template:
export TEMPLATE=Base template name
Replace Base template name with the name of the base template to use for creating the VM.

export VSPHERE_CLUSTER=vSphere cluster name
Replace vSphere cluster name with the name of the vSphere cluster.
7.
Choose the datacenter:

8.
Choose the resource pool:
export RESOURCE_POOL=Resource pool name
Replace Resource pool name with the name of the vSphere resource pool.
9.
Choose the datastore:
export DATASTORE=Datastore name
Replace Datastore name with the name of the vSphere datastore.
10. Choose the network:
export NETWORK=Network name
Replace Network name with the name of the vSphere network.
11. Choose the folder:
export FOLDER=Folder name
Replace Folder name with the name of the vSphere folder.
12. (Optional) Use insecure connection (self-signed certificates):
export INSECURE=true
The NKP CLI can only verify server certificates signed by a trusted CA. Ensure that you allow
insecure access to the vCenter endpoint if the vCenter server certificate is not signed by a trusted CA
certificate.
If the vCenter endpoint uses a self-signed CA certificate, the CA certificate is untrusted.
13. (Required for air-gapped environment and optional for non-air-gapped environment) Create a package
bundle:
NKP requires Operating System packages to be available in the base image. These packages are
available in the package repositories accessible over the internet. As air-gapped environments are
restricted from accessing these package repositories, you must first create a package bundle where
the repositories can be accessed. Then, transfer this bundle to an air-gapped environment to build the
OS image in an air-gapped environment.
Download the NKP air-gapped bundle from the Nutanix portal. For more information, see Downloading
NKP on page 17. This air-gapped bundle contains the NKP artifacts to build the image. Run the
following command in an environment with internet access to fetch and add the operating system
packages, to create a package bundle for NKP.
nkp create package-bundle ${OS_TYPE} --artifacts-
directory path_to_artifacts_bundle_DIR
${FIPS_ENABLED:+--fips}
Replace path_to_artifacts_bundle_DIR with the path to the artifacts bundle directory.
The package bundle contains all the necessary packages and artifacts required to build an NKP
compatible OS image in an air-gapped environment.
