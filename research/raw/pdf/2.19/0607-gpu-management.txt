GPU Scheduling with DRA and MIG
Dynamic Resource Allocation (DRA) is the primary method for advanced GPU scheduling in Nutanix
Kubernetes Platform (NKP), providing explicit, policy-aware allocation of accelerator resources.
NKP supports GPU scheduling through Dynamic Resource Allocation (DRA) and vendor GPU Operators.
DRA is the primary method for advanced GPU scheduling.
Multi-Instance GPU (MIG) behavior can vary across infrastructure, node configurations, and operator
capabilities.
Use the Kubernetes DRA API when you need explicit, policy-aware allocation of accelerator resources,
such as GPUs. DRA separates the resource request, scheduling, and allocation life cycle; therefore,
workloads can bind to accelerator capacity in a controlled and auditable flow.
In NKP v2.19.0 and later, Dynamic Resource Allocation (DRA) is enabled by default because NKP now
ships with Kubernetes v1.36 or later and Containerd v2.1.x. Containerd 2.1.x enables the Container Device
Interface (CDI). You do not need to enable the Kubernetes DRA API. Configure the GPU Operator to use
the DRA driver instead of the device plugin:
•
For NVIDIA GPUs: Deploy the NVIDIA GPU Operator from the AI Catalog and explicitly configure its
Helm values to enable the DRA driver. Configure those values so the DRA driver does not conflict with
the device plugin on the same node pool.
For more information, see the Support Dynamic Resource Allocation (DRA) section in the CNCF AI
Conformance document.

NVIDIA GPU Metrics Monitoring
GPU observability in Nutanix Kubernetes Platform (NKP) depends on the GPU Operator stack, node-
level exporters, and the monitoring pipeline, including the NVIDIA data center GPU manager (DCGM)
integration that exports GPU metrics to Prometheus.
Accurate GPU metrics require all collection components to be healthy and aligned with the node driver and
runtime versions.
By default, Kommander has a Grafana dashboard named NVIDIA DCGM Exporter Dashboard, which
displays the GPU performance and health data. You can access this dashboard from the Kommander
Grafana user interface to monitor GPU metrics across your clusters. For information, see NVIDIA DCGM.
Common GPU metrics available include the following information:
•
GPU utilization percentage by device and node
•
GPU memory used, free, and total capacity
•
GPU temperature and power draw
•
Tensor or compute engine activity (where exposed by the vendor stack)
•
GPU error counters, throttling signals, and health indicators
•
Per-pod or per-container accelerator usage labels where mapping is supported
Review the following collection prerequisites:
•
GPU Operator and device plugin pods are running and healthy.

Exporter pods are running on all intended accelerator nodes.

Prometheus scrape configuration includes exporter targets.
