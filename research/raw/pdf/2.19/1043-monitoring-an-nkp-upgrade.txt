Monitoring an NKP Upgrade
Monitor upgrade stages, application readiness, progress, and errors of a workload cluster from the Nutanix
Kubernetes Platform (NKP) UI or CLI.
Before you begin
Before monitoring an upgrade, verify the following requirements:
•
Ensure that you have the permission to view the workload cluster and its upgrade status.
•
Identify the name and namespace of the workload cluster.
•
For CLI monitoring, use the terminal in which you started the upgrade.
About this task
For a supported ClusterClass workload cluster, the upgrade first updates the platform applications. It then
updates Kubernetes and the cluster infrastructure. The UI and interactive CLI display the progress reported
by the cluster.
A status in the UI can briefly lag behind the current cluster state. You can leave the upgrade page and
return while the upgrade continues.
Note:
A warning can appear while a component is reconciling and can clear without user action.
Investigate a warning that persists or a step that reports an error.
The GitOps-driven upgrades do not generate UpgradePlan resources. As a result, the NKP UI
does not track the upgrade status the way it tracks upgrades initiated directly through the UI or
CLI.
