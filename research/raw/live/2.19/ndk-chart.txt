=== Chart templates ===
Deployment ndk-controller-manager, containers: manager, infra-manager, kube-rbac-proxy, job-scheduler.
Services: ndk-intercom-service (LoadBalancer), ndk-controller-manager-metrics-service, ndk-webhook-service,
  ndk-scheduler-webhook-service. Webhooks: one Mutating, one Validating.
Prechecks (fail the install): CSIDriver csi.nutanix.com version >= 3.7.1 (labels), the PC secret exists in the release
  namespace with key "key" = "<host>:<port>:<user>:<password>" (basic auth) or host/port/auth_type/key_value/key_type
  (service auth), a TLS precheck, an HAA precheck. dryRun=true skips them.
manager-config.yaml: tls.server.mode SECRET + tls.server.clusterName set -> install fails:
  "For NDK installation in mode 'SECRET', clusterName cannot be provided. The DNS subject alternative name (SAN) provided
  in the certificate secret will be used". (The NKP guide p.341 example sets both.)
cert-manager.yaml: tls.server.enable true with mode SELF_SIGNED or ISSUER and no clusterName -> install fails
  ".Values.tls.server.clusterName is required."
controller-manager-metrics-monitor.yaml: with prometheus.enable true it reads .Values.serviceMonitor.customLabels (top level,
  not prometheus.serviceMonitor.customLabels). helm template with prometheus.enable=true and no top-level serviceMonitor:
  "nil pointer evaluating interface {}.customLabels". With --set-json 'serviceMonitor={"customLabels":{}}' it renders
  one ServiceMonitor.
crd-upgrade-hook.yaml: a pre-upgrade Job.
NOTES.txt prints "NDK Pulse Telemetry enabled: <bool>" and the server TLS mode; SELF_SIGNED and DISABLED print a
  "not for production" notice.
