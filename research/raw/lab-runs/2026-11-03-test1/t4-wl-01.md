## Learnings

1. `[nkp-skill nkp-install/references/nutanix.md N5]` **N5 never says how to create the workspace.** Step 1 is "Find the workspace namespaces and the registry mirror of the management cluster" — it assumes the workspace exists. The create step **is** in the skills (`nkp-identity-security`, `references/rbac.md` R5), and the router reaches it, but nothing in `nkp-install` points there. I found R5 only because my brief named it. Fix: in N5 step 1 add "For a new workspace: skill `nkp-identity-security`, `references/rbac.md` R5 (`nkp create workspace`). Then read `WORKSPACE_NS` from the WORKSPACE NAMESPACE column."
2. `[fact]` **`nkp create workspace skilltest-ws` makes the namespace `skilltest-ws-7kr7h`** — the CLI adds a 5-character suffix, so `WORKSPACE_NS` is never `<ws>`. R5's "Done when: the workspace shows a WORKSPACE NAMESPACE" is right, but add the suffix fact and "do not put the workspace name in `WORKSPACE_NS`". `--namespace <name>` pins the namespace; the lab default did not.
3. `[nkp-skill nkp-install/references/nutanix.md N5 + SKILL.md "Set the kubeconfig variables"]` **A workload `nkp create cluster` writes no kubeconfig and prints no success line.** It ends at `✓ Waiting for machines to be ready` and stops; there is no `Cluster was created successfully!` line and no `<cluster>.conf` in `$HOME` (only the management cluster's own `.conf` is there). Two consequences: (a) the `nkp get kubeconfig` block is **mandatory**, not a fallback — say so; (b) an executor that greps for the success line will think the create failed. Also **N5's own text does not give `--timeout`**: the measured workload create is 3 min 20 s, so the 30 min default is fine — say "only the management cluster needs `--timeout 60m`" so the agent does not carry N4's advice over.
4. `[nkp-skill nkp-install/SKILL.md Step: Verify]` For a **workload** cluster the Done-when list is only partly reachable at once. Measured: machines Ready + CAPI `Provisioned` + no non-Running pods at **3–7 min**, but `PHASE Reconciled` and all `KommanderCluster` conditions only at **≤ 38 min**, because `nkp create cluster` returns before the platform apps start. Also `kubectl -n kommander wait helmreleases` waits on the **management** cluster and says nothing about the workload cluster (namespace `kommander` does not exist there). Fix: add a workload-cluster branch — `kubectl --kubeconfig "$CLUSTER_KUBECONFIG" wait --for=condition=Ready helmreleases -A --all --timeout 30m`, `kubectl --kubeconfig "$MGMT_KUBECONFIG" -n "$WORKSPACE_NS" get kommanderclusters` (all conditions True), and state that the `Reconciled` PHASE can take 30–40 min on a workload cluster while it is minutes on a management cluster.
5. `[nkp-skill nkp-install/references/nutanix.md N6]` **The last N6 line is wrong for a workload cluster:** `kubectl --kubeconfig "$MGMT_KUBECONFIG" -n kommander get svc kommander-traefik` — this reads the management cluster. On a workload cluster Traefik runs **on the workload cluster** in the **workspace namespace**: `kubectl --kubeconfig "$CLUSTER_KUBECONFIG" -n "$WORKSPACE_NS" get svc kommander-traefik` (measured: `<net>.62`, ports 8085/5000/80/443, and its HTTP answer is `301` not `200`). Same for the namespace: the platform apps of a workload cluster are HelmReleases **in the workspace namespace on the workload cluster** (`skilltest-ws-7kr7h`), never in `kommander`.
6. `[nkp-skill nkp-install/references/nutanix.md N1, IP plan]` "`LB_IP_RANGE` … The NKP UI gets the first IP" is only true when Traefik is the first `LoadBalancer` Service. Measured here: I created `app-lb` at 8 min and Traefik got **`.62`**, not `.61`. MetalLB allocates in order. Reword: "the first **free** IP; the UI gets the first IP only if nothing else has taken it" — and say that on a workload cluster a day-1 test that runs before the platform apps finish takes `.61`.
7. `[nkp-skill nkp-install/references/nutanix.md N4D]` N4D is written for the management create. A **workload** dry run: no kind bootstrap cluster, no CAPI install, **under 20 s** (vs 3 min 09 s), **5 Secrets** instead of 7 (`prism-central-metadata` and `kommander-bootstrap-configuration` are management-only). Add that so an executor does not wait for a 3-minute bootstrap step or look for the missing Secret.
8. `[nkp-skill kubernetes-core/SKILL.md Step 4]` The server dry run **and** `kubectl diff` of a multi-document file whose first object is a `Namespace` fail for the later objects: `Error from server (NotFound): … namespaces "skilltest-app" not found`. Fix: "apply the Namespace first (`kubectl create namespace`), then dry run and apply the rest", or split the file. Also the `diff` exit-code rule (0/1/>1) is unusable through a pipe — `kubectl diff … | head` printed `diff_rc=0` while the API returned NotFound. Say "run `diff` without a pipe and read `$?`".
9. `[nkp-skill nkp-storage-backup/references/csi.md (~line 238), SKILL.md step 1]` The `custom-columns` `CLAIM:.spec.claimRef.namespace/.spec.claimRef.name` prints **`<none>`** — custom-column paths cannot be joined with `/`. Use `NS:.spec.claimRef.namespace,PVC:.spec.claimRef.name`. Measured on all 4 PVs of the workload cluster.
10. `[nkp-skill nkp-storage-backup + kubernetes-core]` **No skill has a day-1 smoke test.** The task needed "PVC on `nutanix-volume` + a pod that mounts it + a `LoadBalancer` Service + curl". `kubernetes-core` has PVC basics and `Apply a change` but no manifest; `nkp-storage-backup` step 1 only reads state; `nkp-networking`/`metallb.md` M1 only lists Services. Add one short section (in `nkp-storage-backup`, cross-linked from `nkp-networking`) with the manifest that worked: initContainer `busybox:1` writes `/data/index.html`, container `nginx-unprivileged:1.29.5-alpine` mounts the PVC at `/usr/share/nginx/html` on port **8080**, Service 80→8080, then `curl -s -o /dev/null -w '%{http_code}' http://$EXTERNAL_IP/` → `200` with the body from the volume. That single check proves CSI + MetalLB + Cilium in one pass, and the LEADER/`volumeHandle` read.
11. `[nkp-skill nkp-airgap]` **Missing: how to find an image that the site mirror already has.** On an air-gapped site the agent must not pull from the internet and must not guess image paths. What worked: `curl -sk -u "$REGISTRY_MIRROR_USERNAME:$REGISTRY_MIRROR_PASSWORD" "https://<registry-host>/v2/nutanix/<repo>/tags/list"` (the mirror project is the path part of `REGISTRY_URL`; `docker.io/<path>` maps to `<mirror project>/<path>`), plus `kubectl get pods -A -o jsonpath=…images` on the management cluster as the cross-check. Measured hits: `library/busybox:1`, `nginxinc/nginx-unprivileged:1.29.5-alpine`, `mesosphere/kubectl:v1.36.2-alpine`; **404**: `library/nginx`, `library/alpine` (so "nginx" as an image name does not exist in this mirror — the `nginxinc/nginx-unprivileged` name is the one). Also: the Harbor **API** path needs `%252F` for a repository name; the plain `/v2/` tags API does not — mention `/v2/` only. Node proof: the workload cluster pulled `docker.io/nginxinc/nginx-unprivileged:1.29.5-alpine` in **1.044 s** (`Successfully pulled`), so the mirror rewrite of `docker.io/<path>` works.
12. `[fact]` A workload cluster of an Ultimate site runs **19 HelmReleases / 16 AppDeployments** (list in §11) and **122 pods** on 3 CP + 4 workers, all Ready. Put this table in `nkp-install` or `nkp` so an agent can tell "the apps landed" from "half landed". Two of the 16 AppDeployments (`kube-oidc-proxy`, `traefik-forward-auth-kommander`) appear after the first 14, so never treat a first count as final.
13. `[process]` A bash call that did `sleep 240` and then `ssh` in one tool call hung for **27 min** (it had to be killed). The `timeout` on the ssh did not help, because the local `sleep` had already run and the ssh session stopped answering. Rule for lab work: put `sleep N` (N ≤ 120) in its **own** call, wrap each remote command in `timeout`, and add `-o ServerAliveInterval=15 -o ServerAliveCountMax=4`. Cost: ~25 min of the run and one dead session.
14. `[nkp-skill nkp-identity-security/references/rbac.md R5]` R5 is complete and correct for the create (`nkp create workspace`, RC=0 in ~1 s, workspace + namespace made). One line is worth adding: the CLI also accepts `--dry-run` and `-o yaml`, so a plan can be shown as YAML before the real run.
